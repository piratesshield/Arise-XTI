# ==============================================================================
# ⚠️  IMPORTANT — pip `httpx` vs ProjectDiscovery `httpx` NAME COLLISION
# ==============================================================================
# The Python `httpx` package (pulled in TRANSITIVELY by `anthropic`, and by
# `schemathesis`) installs a console script literally named `httpx` into the
# active environment's bin/ directory. If that bin/ sits ahead of ~/go/bin (or
# ~/.pdtm/go/bin) on PATH, then `httpx` in easm-pipeline.sh resolves to the
# Python client instead of the ProjectDiscovery Go binary the recon pipeline
# needs — HTTP discovery breaks.
#
# The fix is ISOLATION — install the Python side in its own virtualenv so its
# bin/ (with the pip `httpx` script) never joins the recon PATH:
#
#   python3 -m venv .venv-apitest              # separate env, see below
#   .venv-apitest/bin/pip install -r requirements-apitest.txt
#
# For the DASHBOARD (which needs `anthropic` -> httpx lib), prefer running it in
# its own venv too, and always keep the ProjectDiscovery bin dir FIRST on PATH:
#   export PATH="$HOME/go/bin:$HOME/.pdtm/go/bin:$PATH"
# Verify the winner is the Go binary:  file "$(command -v httpx)"  # -> ELF/Mach-O
#
# `verify-tools.sh` / `verify_mac_deps.sh` check this collision automatically.
# ==============================================================================
